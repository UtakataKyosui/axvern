# 要件定義・スコープ

> 出典: 2026-10-13時点の統合版 `REQUIREMENTS.md`。要件ID・受入条件IDは維持。

## 開発フェーズ（優先順位の正本）

| バージョン | 目的 | 必須の範囲 |
| --- | --- | --- |
| v0.1 | **実行する** | Pueueでバックグラウンド実行・状態管理・基本的なガード |
| v0.2 | **調べる** | Rust製CLIを組み合わせたファイル／コードベース調査 |
| v0.3 | **結果を活用する** | ログ一時保存・検索・部分抽出・再取得 |
| v0.4+ | **改善する** | 性能計測、ベースライン比較、ボトルネック調査 |

フェーズごとの必須条件と実装順序は [ROADMAP.md](./ROADMAP.md) を正本とする。機能要件IDを残すことは、その機能をv0.1に前倒しして実装する意味ではない。

## 1. 目的

**axvernは、Coding Agentが開発作業を効率的に実行・調査し、将来的に性能を測定・比較・改善できるよう支援するRust製開発最適化ハーネスである。** 初期段階ではPueueによる非同期実行、次に既存Rust製CLIによるコードベース調査、続いて結果の一時保存・検索、最後に性能分析を段階的に提供する。

既存ツールへの委譲を優先し、axvern自身はPueueのプロセス管理、キュー制御、デーモン、ログ記録機構を再実装しない。axvern固有の価値は、実行前のポリシー評価、互換性を検証したモダンCLIへの実行委譲、タスク識別、ログの選択的抽出、診断、機械可読な応答にある。

### 1.1 解決する課題

| ID | 課題 | 目標状態 |
| --- | --- | --- |
| P-01 | Coding Agentが長時間実行コマンドの終了まで待つ | バックグラウンドで起動し、後から状態と結果を確認できる |
| P-02 | テスト・ビルドログが大量に返り、Agentのコンテキストを消費する | 実行IDを返し、必要な行だけ取り出せる |
| P-03 | 後からログを調べる際、コマンドを再実行してしまう | 保存済みログへ繰り返しクエリできる |
| P-04 | 実行許可の判断が一貫しない | Allow / Ask / Denyのポリシーを適用できる |
| P-05 | Pueueデーモンや設定の不備で静かに失敗する | 自己診断で原因と対処を示す |
| P-09 | 指定パスを把握するために複数の一覧・統計コマンドを手で実行する必要がある | 一度の操作で構造とコード統計を取得できる |
| P-06 | スクリプトやJSON解析がAgentごとにばらつく | 安定したコマンド契約と機械可読な応答を提供する |
| P-07 | `ls`・`find`・`grep`などの出力・引数にAgentごとの揺れがある | 適切な場面では `eza`・`fd`・`rg` などに委譲する |
| P-08 | モダンCLIの便利な操作を毎回個別に組み立てる必要がある | 用途別の専用サブコマンドから一貫した結果を得られる |

### 1.2 設計原則

1. **Pueueに委譲する**：タスク登録、状態遷移、キュー、バックグラウンド実行、基本ログ保持はPueueが担当する。
2. **結果を再実行しない**：`query`/`recall`は保存済みの出力のみを参照する。
3. **情報の出所を明示する**：返却する抽出行には実行ID、行番号、抽出条件、ログの取得時点を付ける。
4. **操作を明示する**：axvernのコマンドを通らないPueueタスクはポリシー対象外である。
5. **隔離を誤認させない**：Native実行のポリシーはOSのサンドボックスではない。DockerはMVPでは対象外。
6. **意味を勝手に変えない**：CLI置換は互換性が検証された操作だけに適用し、未知のオプション・構文は元コマンドを維持するか明示的に拒否する。置換後のコマンドも実行前ポリシーで評価する。
7. **未実装の保証をしない**：Pueueの保持期間を超えたログ、統合ログからのstdout/stderr復元、シェル経由のコマンド意味保持を無条件に保証しない。


## 2. システム境界とスコープ

### 2.1 責務の分担

| コンポーネント | 所有する責務 |
| --- | --- |
| axvern | CLI、実行前ポリシー、Pueue Adapter、axvern実行ID対応付け、クエリ・抽出、自己診断 |
| Pueue / pueued | コマンド実行、キュー、バックグラウンドタスク管理、実行状態、基本ログ保存 |
| Devbox | 開発ツールチェーンと依存パッケージ |
| moonrepo | ワークスペース横断のビルド・テスト等のタスク定義 |
| pnpm / Cargo | JS/TS・Rustのパッケージ依存管理 |
| lefthook | Git Hooksによる品質チェック |
| eza / fd / ripgrep | MVPでファイル一覧・パス探索・テキスト検索を委譲する実行先 |
| bat / ast-grep | ファイル内容閲覧・構文検索のMVP追加候補（専用操作のみ） |
| sd / tokei / dust / procs / delta | v0.2で検討する置換・統計・診断・差分ツール |
| rip / zoxide / bottom / hyperfine / xh | 別途設計が必要な将来候補。無条件の自動置換対象外 |

### 2.2 MVPに含める機能

- Pueueへのコマンド登録とバックグラウンド実行（`run`）
- axvern実行IDからPueueタスクIDへの対応付け
- タスク状態の照会（`status`）、終了待機（`wait`）
- 実行前のAllow / Ask / Deny判定（`policy check`）
- Pueue保存ログの行・文字列・末尾・エラー候補抽出（`query`）
- 元ログの表示（`recall`）
- axvern管理タスクの一覧（`history`）
- Pueueおよびaxvern設定の診断（`doctor`）
- 厳格な許可リストに基づくモダンCLIへの任意の自動委譲（`run` に適用）
- ファイル一覧・ファイル探索・テキスト検索の専用サブコマンド（`fs list`、`fs find`、`fs search`）
- ファイル部分閲覧 `fs read` とAST構造検索 `code search` のMVP追加候補（Spike合格後にMustへ昇格）

### 2.3 MVPの対象外

- `--dry-run`、実行結果の事前予測
- Native以外のランタイム、Docker/Dev Containerの自動起動
- 独自のバックグラウンドプロセスマネージャーやスケジューラー
- Pueueを置き換える独立したプロセス・ログ保存デーモン
- RTK連携、LLMによる要約、意味検索、独自SQL/DSL
- シェル文字列・パイプラインの自動解析と書換え、OSコマンドのグローバルなalias/PATH差し替え
- `ls`/`find`/`grep`等の全引数・全動作の完全互換、任意コマンドへの強制置換
- ファイル一括書換え、削除、対話TUI、ベンチマーク実行の自動化
- Claude Code / Codex Hookの自動導入、Agent Loop
- OpenTelemetry送信、Web UI、独自Scaffolding CLI
- Pueueが保持する統合ログからstdoutとstderrを完全に復元する保証


## 7. 非機能要件

| ID | 分類 | 要件 |
| --- | --- | --- |
| NFR-001 | 正確性 | 元コマンドを意図せず二重登録・二重実行しない |
| NFR-002 | 安全性 | シェルメタ文字を単純連結せず、解釈不能な要求を拒否する |
| NFR-003 | 安全性 | ポリシー設定異常時にPueueへ登録しない |
| NFR-004 | プライバシー | タスク履歴・ログから秘密情報が漏れる可能性を明記し、保存領域の権限を制限する |
| NFR-005 | 信頼性 | Pueue不在、デーモン停止、ログ消去を明示的なエラーとして扱う |
| NFR-006 | 操作性 | 人間向けの表示と機械可読なJSONの役割を分離する |
| NFR-007 | 移植性 | Linux/macOSでの利用を目標とし、Pueue互換性を実機検証する |
| NFR-008 | 性能 | 巨大ログを全量メモリ展開せずに抽出可能な方式を優先する。利用APIの制約はSpikeで確認 |
| NFR-009 | 保守性 | Pueueコマンド呼び出し・出力解析をAdapter境界に閉じる |
| NFR-010 | 拡張性 | Docker RuntimeやAgent Adapterを追加してもQuery/Policyを再利用できる |
| NFR-011 | 一時性 | ログ寿命はPueueに従い、axvern独自の無期限保存をデフォルトで作らない |
| NFR-012 | 互換性 | モダンCLIの不完全な互換性による意味変更や破壊的副作用を防ぐため、未検証の置換を実施しない |
| NFR-013 | 追跡可能性 | 元の要求、変換後の実コマンド、ルールID、実行IDを対応付けて表示できる |
