## 4. 機能要件

優先度は **Must**（当該フェーズの必須）、**Should**（推奨）、**Could**（候補）とする。導入順序はROADMAP.mdに従う。

### 4.1 Pueueによるタスク登録と状態管理（FR-RUN）

| ID | 優先度 | 要件 |
| --- | --- | --- |
| FR-RUN-001 | Must | プログラムと引数を指定してPueueへタスクを登録できる |
| FR-RUN-002 | Must | 登録前にaxvernの実行ポリシーを評価する |
| FR-RUN-003 | Must | 登録成功時に一意なaxvern実行IDとPueueタスクIDを取得・対応付けする |
| FR-RUN-004 | Must | 登録後はコマンドの完了を待たずに制御を呼び出し元へ返す |
| FR-RUN-005 | Must | Queued / Running / Done / Failed等のPueue状態をaxvernの安定した状態モデルに正規化する |
| FR-RUN-006 | Must | 指定タスクの完了待機と待機タイムアウトを提供する。待機タイムアウト自体はジョブを停止しない |
| FR-RUN-007 | Must | Pueue CLI/デーモンのエラーと、実行対象コマンドの失敗を区別する |
| FR-RUN-008 | Must | 未知のタスクID、Pueueから削除済みのタスクIDを識別可能なエラーで返す |
| FR-RUN-009 | Must | タスクのカレントディレクトリを指定または引き継げる |
| FR-RUN-010 | Should | タスクの登録・状態・終了コード・開始終了時刻を機械可読形式で取得できる |
| FR-RUN-011 | Must | 引数の空白・引用符・シェルメタ文字を、安全に引き渡す。実装可能な範囲をSpikeで検証し、曖昧な入力は拒否する |
| FR-RUN-012 | Must | axvernの実行IDはPueueの整数タスクIDと区別され、他ユーザーのPueueタスクを誤参照しない |

**注意**：Pueueはシェルコマンドとして実行する。`axvern run -- <program> [args...]` を採用する場合、引数配列を単純連結してはいけない。Pueueのエスケープ機構を検証し、引数の意味を保てないコマンドはMVPで拒否する。

### 4.2 実行ポリシー（FR-POL）

| ID | 優先度 | 要件 |
| --- | --- | --- |
| FR-POL-001 | Must | Allow / Ask / Denyを判定できる |
| FR-POL-002 | Must | コマンド名・引数パターンのルールを定義できる |
| FR-POL-003 | Must | Deny > Ask > Allow の優先順位を守る |
| FR-POL-004 | Must | 一致ルールがなければデフォルトAskとする |
| FR-POL-005 | Must | Askは対話時に承認要求し、非対話時は拒否する |
| FR-POL-006 | Must | Deny/承認拒否時にはPueueにタスク登録しない |
| FR-POL-007 | Must | `policy check` は実行や登録を伴わず、理由とルールIDを返す |
| FR-POL-008 | Must | 不正なポリシー設定があれば登録を拒否する（fail closed） |
| FR-POL-009 | Must | `sh -c` / `bash -c` 等の任意シェル評価を既定で拒否し、明示的な扱いがない限り通さない |

ポリシーはaxvern経由の登録だけを制御する。Pueueへ直接登録されたタスクや、許可後に実行されるプログラム内部の副作用は保証範囲外。

### 4.3 保存済みログのクエリ（FR-QUERY）

| ID | 優先度 | 要件 |
| --- | --- | --- |
| FR-QUERY-001 | Must | Pueueが保持するタスクログを、axvern実行IDから取得できる |
| FR-QUERY-002 | Must | キーワードのリテラル検索ができる |
| FR-QUERY-003 | Must | ログ末尾のN行を取得できる |
| FR-QUERY-004 | Must | 開始行と取得行数を指定できる |
| FR-QUERY-005 | Must | エラー候補行を決定論的なルールで抽出できる |
| FR-QUERY-006 | Must | 抽出結果へ元ログ行番号、タスクID、抽出条件を含める |
| FR-QUERY-007 | Must | `query` / `recall` は対象コマンドを再実行しない |
| FR-QUERY-008 | Must | `recall` でPueueに残る完全ログを取得できる（未保持時は明示的エラー） |
| FR-QUERY-009 | Must | 出力の最大行数/最大バイト数を制限できる。省略時にも安全な上限を持つ |
| FR-QUERY-010 | Must | 実行途中のログを参照するときは、取得時点と不完全な可能性を明示する |
| FR-QUERY-011 | Must | Pueueのログが統合ストリームである場合、stdout/stderrを区別したと誤表示しない |
| FR-QUERY-012 | Should | `--format json` で構造化した抽出結果を返す |
| FR-QUERY-013 | Must | ログが削除済み、取得不能、文字列化不能である場合に区別可能な結果を返す |

**完全保存の境界**：ログの保存と削除はPueueの責務であり、axvern v0.1は独立したバックアップを保証しない。`recall` は「現存するPueueログの再取得」を意味する。元ログが失われた場合、復元可能と表示しない。

### 4.4 対応付けと履歴（FR-INDEX）

| ID | 優先度 | 要件 |
| --- | --- | --- |
| FR-IDX-001 | Must | axvern実行ID、PueueタスクID、登録日時、作業ディレクトリを対応付けて保存する |
| FR-IDX-002 | Must | `history` はaxvernで登録したタスクのみを表示する |
| FR-IDX-003 | Must | Pueue側の`clean`/`reset`等でタスクが消えた場合に失効状態を判定できる |
| FR-IDX-004 | Must | 対応付け情報へのアクセスは同一ユーザーに制限する |
| FR-IDX-005 | Should | 古い対応付け情報の整理手順を提供する |

**保存方式**は実装設計事項。MVPではローカルの小さなメタデータファイルまたはSQLiteを比較して決定する。ログ本文を二重保存しない。

| --- | --- | --- |
| FR-DOC-001 | Must | Pueue CLIがインストールされていることを確認する |
| FR-DOC-002 | Must | pueuedへの疎通と基本状態取得を検証する |
| FR-DOC-003 | Must | axvern設定、ポリシー定義の妥当性を検証する |

| FR-DOC-007 | Must | 人間向け出力とJSON形式を提供する |

### 4.6 モダンCLI委譲（FR-MOD）

既存コマンドの自動置換は **初期状態では無効（明示的opt-in）** とする。MVPで自動置換を許すのは、引数の意味と出力契約を検証できた限定的なコマンド形式だけである。`find`と`fd`は引数構文も隠しファイル・`.gitignore`の扱いも異なるため、汎用の自動置換は行わない。

| ID | 優先度 | 要件 |
| --- | --- | --- |
| FR-MOD-001 | Must | コマンド置換の有効・無効を設定でき、既定値は無効である |
| FR-MOD-002 | Must | 許可リストにある「プログラム・引数の組合せ」に限って置換できる |
| FR-MOD-003 | Must | 不明なオプション、シェル式、引数非互換の要求を暗黙に変換しない |
| FR-MOD-004 | Must | **元コマンドと実際に登録するコマンドの双方**に実行ポリシーを適用する |
| FR-MOD-005 | Must | 置換後のコマンド名・引数と、適用ルールIDを実行メタデータに記録する |
| FR-MOD-006 | Must | 必要なCLIが利用できない場合は黙って互換性を偽らず、置換をスキップするか明示的エラーを返す |
| FR-MOD-007 | Must | コマンド置換が発生してもPueueへは1タスクだけ登録する |
| FR-MOD-008 | Should | `doctor`が置換ルールと実行先CLIの導入状況を診断する |

**MVPの候補：** `ls` の引数なし等、互換性を確認した最小形式 → `eza`。`grep → rg` と `find → fd` の汎用置換は対象外。環境変数やリダイレクトを含むシェルスクリプト本文は書き換えない。Pueueでのコマンド登録時のシェルエスケープは別途Spikeで確認する。

### 4.7 専用ファイル操作コマンド（FR-FS）

汎用の置換とは別に、axvern自身のサブコマンドとして**目的が明確な操作**を提供する。内部ではRust製の既存CLIに委譲するが、それらのすべてのオプションを公開する必要はない。これらもPueue経由で登録し、実行IDから結果を再検索できるものとする。

| ID | 優先度 | 要件 |
| --- | --- | --- |
| FR-FS-001 | Must | `fs list [path]` でディレクトリの項目一覧を取得できる（ezaを使用） |
| FR-FS-002 | Must | `fs find <pattern> [path]` でファイル名・パスの探索を実行できる（fdを使用） |
| FR-FS-003 | Must | `fs search <pattern> [path]` でファイル内テキストを検索できる（ripgrepを使用） |
| FR-FS-004 | Must | 専用サブコマンドのオプションは各ツールの引数へ明示的・安全に対応付ける |
| FR-FS-005 | Must | 隠しファイル・ignoreルールなど、検索対象のデフォルト条件を明示する |
| FR-FS-006 | Must | サブコマンドもPolicy → Pueue → 保存ログ → Queryの経路を利用する |
| FR-FS-007 | Must | 実行先が未導入の場合、具体的な不足コマンドと導入方法を示す |
| FR-FS-008 | Should | 人間向け表示に加え、出力が正しく構造化できる場合はJSONを提供する |

特に`fd`は既定で隠しファイルとignore対象を除外する。この挙動を`find`と同一視しない。`fs find`は`fd`本来のデフォルトを採用し、探索対象を広げるフラグを明示的に提供する。

### 4.8 モダンCLIの候補・採用基準（FR-TOOLS）

CLIの採用目的は「Rust製だから」ではなく、**Coding Agent向けの安定したデータ抽出・出力制限・用途別操作**にある。ユーザーの通常のシェル環境や既存コマンドの挙動を全体的に上書きしない。

| フェーズ | ツール | 用途 | axvernでの扱い |
| --- | --- | --- | --- |
| MVP Must | `eza` | ファイル一覧 | `fs list`。安全に確認できた引数形式のみ`ls`から自動置換候補 |
| MVP Must | `fd` | ファイル名・パス探索 | `fs find`。`find`からの包括的自動置換はしない |
| MVP Must | `rg`（ripgrep） | テキスト検索 | `fs search`。`grep`の包括的自動置換はしない |
| MVP Should | `bat` | ファイル内容の限定的閲覧 | `fs read`。色・ページャを無効化し行番号と範囲を制御 |
| MVP Should | `ast-grep` (`sg`) | ASTに基づくコード検索 | `code search`。対応言語・パターンの妥当性を確認 |
| v0.2 Could | `sd` | 正規表現による文字列置換 | 明示的な編集用操作のみ。`sed`の自動置換は禁止 |
| v0.2 Must | `tokei` | 言語別コード行数・統計 | `code stats`、`fs analyze`の言語統計 |
| v0.2 Could | `dust` | ディスク利用状況の要約 | `system disk-usage`等を検討 |
| v0.2 Could | `procs` | プロセス一覧・検索 | `system processes`等を検討 |
| v0.2 Could | `delta` | 差分の可読化 | `code diff`等。Git差分の意味を変更しない |
| Future | `rip` | 復元可能な削除 | 破壊的操作であり既定ポリシーでは拒否・確認を優先 |
| Future | `zoxide` | ディレクトリ移動 | シェル状態への依存があるため自動置換しない |
| Future | `bottom` (`btm`) | 対話的なプロセス監視 | 非対話的な構造化出力との適合性を先に検証 |
| Future | `hyperfine` | 実行時間のベンチマーク | 対象コマンドが複数回実行されることを明示した場合だけ利用 |
| Future | `xh` | HTTPリクエスト | 通信先・認証情報・副作用を評価した上で明示的に使用 |

**注意事項**：`bat`、`ast-grep`を導入しても`cat`や`grep`のすべての呼び出しを自動変換しない。`sd`はファイル変更を伴う可能性がある。`delta`は表示変換、`zoxide`はシェル統合、`bottom`は対話TUIであり、Pueue経由の一時ログ抽出と適合するとは限らない。ツールごとに色・ページャ・終了コード・JSON出力の有無を検証する。

| ID | 優先度 | 要件 |
| --- | --- | --- |
| FR-TOOLS-001 | Must | 各ツールの用途・バージョン・有効/無効・依存関係を診断可能にする |
| FR-TOOLS-002 | Must | 自動置換と明示サブコマンドを分け、変換前後のコマンドと根拠を追跡する |
| FR-TOOLS-003 | Must | Pueueで非対話実行する際に色・ページャ・TTY依存挙動を制御する |
| FR-TOOLS-004 | Should | `fs read`でファイルの指定行範囲だけを取得する。対象パスと範囲を記録する |
| FR-TOOLS-005 | Should | `code search`でAST検索を行い、対応言語・解析エラーを明示する |
| FR-TOOLS-006 | Could | `code stats`で言語別コード統計を取得する |
| FR-TOOLS-007 | Must | 書込み・削除・ネットワーク送信・繰り返し実行を伴うCLIを読み取り操作として偽装しない |

### 4.9 パス分析（FR-ANL、v0.2 Must）

`axvern fs analyze <path>` は既存のCLIを組み合わせた **決定論的なパスの概要調査** を提供する。独自のコード解析エンジン、LLMによる推定、依存グラフ構築はMVP・v0.2では作らない。`tokei`のJSON形式の言語別コード統計、`eza`のツリー表示、`fd`による代表的なプロジェクト設定ファイルの発見を利用する。容量の詳細分析が必要なときのみ`dust`を追加で使用できる（Should）。

| ID | 優先度 | 要件 |
| --- | --- | --- |
| FR-ANL-001 | Must | ファイルまたはディレクトリを指定して分析できる |
| FR-ANL-002 | Must | `tokei`から言語別のファイル数・コード行数・コメント数を取得できる |
| FR-ANL-003 | Must | `eza`から深さを制限したディレクトリツリーを取得できる |
| FR-ANL-004 | Must | `fd`から `Cargo.toml`、`package.json`、`pnpm-workspace.yaml`、`devbox.json` 等の構成ファイルの所在を取得できる |
| FR-ANL-005 | Must | JSON出力で `path`、`summary`、`languages`、`tree`、`manifests`、`warnings`、`execution_id` を区別する |
| FR-ANL-006 | Must | 各子コマンドはPolicy評価後にPueueへ登録し、結果を後から照会できる。複数の子タスクIDと親分析IDを対応付ける |
| FR-ANL-007 | Must | `--max-depth` と出力件数上限を設け、隠しファイルとignore対象の扱いを明示する |
| FR-ANL-008 | Must | 存在しないパス、アクセス拒否、子コマンド失敗、部分的な分析成功を区別する |
| FR-ANL-009 | Must | ディレクトリ構造の表示深度と集計対象の走査範囲は別々に明示し、集計がツリー表示に限定されると誤解させない |
| FR-ANL-010 | Should | `dust`を使ってディレクトリ単位のディスク使用量を補完できる |

**運用契約：** 分析結果は子コマンド実行時点のスナップショットであり、途中でファイルが更新されれば数値が一致しない可能性がある。結果には取得時刻・使用ツール名・部分成功の警告を記載する。`tokei` と `fd` のignore規則を同一視せず、集計範囲の相違を明示する。ファイルやディレクトリのシンボリックリンクは既定では辿らず、ループおよび対象外パスの走査を防ぐ。`eza`の可読テキスト表示は不安定なJSONパーサーで再解析せず、ツリー表現として保持する。

### 4.10 CLIへの段階的追加基準

新規ツールをMustに引き上げる条件は、(1) 公式CLIで同等用途が確認できる、(2) `axvern`の引数から安全に変換できる、(3) 実行出力をPueueログから再取得できる、(4) ポリシーとDoctorが連動する、(5) 受入テストで非対話の挙動を検証できる、の5項目とする。満たさない場合はShould/Couldとして残す。
