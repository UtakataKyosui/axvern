# 受入テスト・技術検証

> 出典: 2026-10-13時点の統合版 `REQUIREMENTS.md`。要件ID・受入条件IDは維持。

## 8. 受入テスト

| ID | シナリオ | 合格条件 |
| --- | --- | --- |
| AC-01 | 長時間コマンドを登録 | コマンド完了前に実行IDを返す |
| AC-02 | Pueueタスク対応付け | 実行IDから正しいPueueタスクを一意に解決できる |
| AC-03 | `status`確認 | Queued/Running/Done等を正しく区別する |
| AC-04 | `wait --timeout` | 待機タイムアウトでもタスクを停止しない |
| AC-05 | Deny対象を登録 | Pueueタスクが新規作成されない |
| AC-06 | Ask対象を非対話登録 | 自動承認されずタスクも登録されない |
| AC-07 | シェル特殊文字を含む引数 | 意味を壊さず実行、または安全に拒否する |
| AC-08 | 失敗したテストログを検索 | 一致行・行番号と実行IDが返る |
| AC-09 | 同じログへ複数回クエリ | 元コマンドを再実行せず別条件で抽出できる |
| AC-10 | ログが削除された後に`recall` | 消失を明示し、実行結果を捏造しない |
| AC-11 | 稼働中ログへのクエリ | 部分的なログであることを明示できる |
| AC-12 | 大量ログ | 応答サイズを抑え、プロセスが過大なメモリを消費しない |
| AC-13 | pueued停止 | `doctor`がFailと修復案を返す |
| AC-14 | JSON出力 | 安定した状態名・識別子を持ち、機械的にパースできる |
| AC-15 | 外部Pueueタスクの存在 | `history`に誤混入しない |
| AC-16 | 置換機能の初期状態 | 未設定では元のコマンドが実行される |
| AC-17 | 許可リストに一致するコマンド | 有効化した場合のみ指定したRust製CLIで1回実行される |
| AC-18 | 未知の`find`オプション | `fd`へ勝手に変換しない |
| AC-19 | 変換後にDenyへ一致 | Pueueへの登録を拒否する |
| AC-20 | `fs list` / `fs find` / `fs search` | それぞれeza/fd/rgへ委譲し、結果を実行IDで問い合わせられる |
| AC-21 | 隠しファイル・ignore対象の検証 | `fs find` / `fs search`の対象がオプション通りになる |
| AC-22 | 対象CLI未導入 | `doctor`と実行失敗時に不足ツールを特定できる |
| AC-23 | `fs read`（Should） | 指定範囲だけ返し、端末制御文字・ページャを含めない |
| AC-24 | `code search`（Should） | 対応言語のASTパターンで一致箇所を返し、構文エラーを正しく報告する |
| AC-25 | 書込みを伴うCLI | 安全な読み取りコマンドとして自動変換されず、Policyが適用される |
| AC-26 | `hyperfine`等の反復実行 | 自動実行対象に含まれず、再実行の副作用を発生させない |


## 9. 技術検証（実装前のSpike）

次の検証に合格しない限り、Pueue Adapterの本実装を開始しない。

1. **登録の正確性**：`pueue add`のエスケープ/シェル解釈を、空白、引用符、改行、メタ文字、Unicodeを含む引数で確認する。
2. **タスクID取得**：タスクIDを構造化して取得できる方法を確認する。表示文言の正規表現パースに依存しない方式を優先する。
3. **JSON契約**：`pueue status --json`および`pueue log ... --json`の形式と対象バージョンを固定する。
4. **ログ可用性**：稼働中・完了後・`clean`/`reset`後のログ取得可能性を検証する。
5. **統合ストリーム**：stdoutとstderrが統合される前提で、ログの行番号・並び・改行境界を検証する。
6. **サイズと性能**：大容量ログの部分取得の性能と、全量取得が必要になる境界を計測する。
7. **プロセス終了状態**：子プロセス失敗、kill、Pueue daemon異常、待機タイムアウトを区別できるか確認する。
8. **環境再現性**：Devboxで指定バージョンのPueue CLI/daemonを導入し、Linux/macOSで動作を確認する。
9. **CLI差異**：`ls/eza`、`find/fd`、`grep/rg`の構文・終了コード・隠しファイル・ignore動作の違いを調べ、許可する自動置換を最小限に限定する。
10. **専用操作**：`fs`サブコマンドの出力に色制御・非対話モード・制限サイズを適用し、Pueue経由で安全に取り出せるか確認する。
11. **bat**：ページャ・色・行番号・切り出し範囲を非対話で制御できるか検証する。
12. **ast-grep**：対象言語・構文パターン・機械可読な出力・終了状態を確認する。
13. **将来候補**：`sd`等のファイル変更、`rip`等の削除、`xh`の通信、`hyperfine`の反復実行を、読み取り専用操作と明確に区別できるか確認する。

Spikeで不適合が見つかった場合は、Pueueの利用範囲を縮小するか、該当要件を再審議する。未検証の挙動を実装前提として扱わない。
