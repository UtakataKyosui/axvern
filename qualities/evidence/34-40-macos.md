## Operational boundaries

Linux acceptance is by the Quality workflow (ubuntu-latest and macos-latest) on the pull request. Pueue retains full raw logs independently; saved results are bounded combined previews. Keep the axvern runner binary at its registered path until queued tasks finish. A killed runner can leave an active spool reservation; investigate manually rather than silently deleting/resubmitting it. Metadata/tombstones are not automatically pruned, and disk allocation overhead is not an absolute quota guarantee. New work is refused on detected metadata capacity exhaustion; later persistence failure is distinct from target failure. Discovery/performance tool compatibility requires the corresponding future adapter spikes. This file records local implementation evidence, not remote Issue closure or release approval.

## API migration

#112 (2026-10-28): `ExecutionService::run(plan, interactive, approval)` registered the target directly and bypassed output capture and capacity reservation. It is now `run(runner, plan, interactive, approval)` and delegates to `run_captured`; callers pass the internal worker executable as `runner`. Reverting the delegation makes the concurrent-capacity test register all six runs instead of one. `store::register_and_save` remains a low-level registration primitive without capture or reservation.
